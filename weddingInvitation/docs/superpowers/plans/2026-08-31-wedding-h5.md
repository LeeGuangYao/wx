# Wedding H5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a deployable, mobile-first, four-section wedding invitation H5 for 李光耀 and 方紫薇, with one cover photo, clear wedding details, restrained reveal motion, and a working Amap search link.

**Architecture:** Use the current repository directory as a Vue 3 + Vite static-site root. `App.vue` only composes four focused section components; all wedding content comes from a typed config; map URL creation and reveal behavior stay in isolated utilities/composables. The production output is a portable `dist/` directory with relative asset paths.

**Tech Stack:** Vue 3, Vite, TypeScript, SCSS, Vitest, browser-native `IntersectionObserver`, Amap URI API.

**Spec:** [`wedding-h5-docs/wedding-h5-prd.md`](../../../wedding-h5-docs/wedding-h5-prd.md) and [`wedding-h5-docs/wedding-h5-technical-design.md`](../../../wedding-h5-docs/wedding-h5-technical-design.md)

## Global Constraints

- The page has exactly four main sections: Hero, Invitation, Wedding Details, and Closing.
- Do not add music, video, galleries, countdowns, RSVP, guestbook, payment, login, router, state management, server, database, UI kit, or animation framework.
- Display the confirmed copy exactly as written in the PRD; keep all mutable wedding data in `src/config/wedding.ts`.
- Use a single project-local image named `src/assets/images/wedding-cover.jpg`; never reference `/Volumes/...` at runtime and never modify the source image.
- Mobile is primary. Verify widths 360, 375, 390, 412, and 430 px; desktop content remains centered and no wider than 480 px.
- Support `prefers-reduced-motion`, `IntersectionObserver` absence, safe areas, visible focus, semantic headings, a meaningful image alt, and a minimum 44×44 px navigation target.
- Keep the visual language warm-white, low-saturation, spacious, and type-led; do not introduce traditional red/gold wedding-template decoration.
- Do not lazy-load the LCP cover image; use a stable image container and `fetchpriority="high"`.
- Production verification requires unit tests, type checking, a production build, production-preview inspection, and real-device navigation checks.

import type { WeddingVenue } from '@/types/wedding'

const AMAP_SEARCH_ENDPOINT = 'https://uri.amap.com/search'

export function createAmapSearchUrl(venue: WeddingVenue): string {
  const params = new URLSearchParams({
    keyword: `${venue.name} ${venue.address}`,
    view: 'map',
    src: 'wedding-invitation',
    callnative: '1',
  })

  return `${AMAP_SEARCH_ENDPOINT}?${params.toString()}`
}

export function openWeddingNavigation(venue: WeddingVenue): void {
  window.location.href = createAmapSearchUrl(venue)
}
```

import { onBeforeUnmount, onMounted, type Ref } from 'vue'

export function useReveal(target: Ref<HTMLElement | null>): void {
  let observer: IntersectionObserver | undefined

  onMounted(() => {
    const element = target.value
    if (!element) return

    const reduceMotion = window.matchMedia?.('(prefers-reduced-motion: reduce)').matches ?? false
    if (reduceMotion || !('IntersectionObserver' in window)) {
      element.classList.add('is-visible')
      return
    }

    observer = new IntersectionObserver(
      ([entry]) => {
        if (!entry?.isIntersecting) return
        element.classList.add('is-visible')
        observer?.unobserve(element)
      },
      { threshold: 0.18 },
    )

    observer.observe(element)
  })

  onBeforeUnmount(() => observer?.disconnect())
}
```
